# 2026-10-21

## PersonalRAG-v2 代码审查（Python 骨架 + init_sql）

**实测环境**：本地 PG 18.6（127.0.0.1:15432，库 personalrag_v2），`.venv` = Python 3.11.15，rag schema 已装（10 表 / 10 表 FORCE RLS / 0 用户）。

**已确认的缺陷（附证据）**
1. `.env` 未被 `.gitignore` 忽略，仓库尚无首次提交 → 首次 commit 会把 DB 密码带入 git。
2. `config.py` 用 `load_dotenv(".env", override=True)`：相对 CWD，从其他目录启动直接 `ValueError: 缺少环境变量`；override=True 使真实环境变量被 .env 覆盖（实测 shell 注入被无视）。
3. `main.py` 的"业务阶段验证"是假通过：UUID `0000...0001` 在 users 表不存在（库内 0 用户），打印的是刚 set 进去的 `current_setting`，不证明 RLS。
4. 依赖写成 `dotenv>=0.9.9`（废弃转发包）而非 `python-dotenv`（能跑是因为它依赖后者）。
5. `db.py` 每次 with 都新建并 close 连接（实测 conn.closed=True），无连接池；事务内调 `conn.commit()` 会抛 `Explicit commit() forbidden`。

**已确认正常的部分**：auth 连接只读有效（拦截 CREATE TABLE）；无 app.user_id 时 RLS 默认拒绝（0 行）；`set_config(...,true)` 在事务/回滚后不残留（泄漏检查 = null）；Settings repr 已遮蔽 DSN。

**SQL 层风险（待决策，未改动）**
- `UNIQUE(user_id,source_type,source_key)` 不含 deleted_at → 软删除后同源重导会 23505，建议改 partial unique index。
- HNSW 全局索引 + RLS 索引后过滤 → 多租户 top-k 召回衰减。
- `answer_one_running_per_conversation` 限制同会话仅一个 running，需确认是否有意。
- `conversations.next_message_sequence` 无 DB 层原子取号，应用侧需 `UPDATE ... RETURNING`。
