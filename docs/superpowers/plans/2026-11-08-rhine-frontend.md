# Rhine 前端移植实施记录

**目标：** 将 rhine-lock 的三维雕塑、档案玻璃与终端视觉移植到 PersonalRAG Vue 3 前端，保留已有业务与认证接口，仅本地实现。

**来源：** https://github.com/tmc5csxr9m-cpu/rhine-lock ，commit a4df68c6bd9e01ecb7660659becf495957e57faa，AGPL-3.0-or-later。

## 设计

直接复用 Stage.ts 和 shaders.ts，并在 Vue 组件中管理生命周期；不引入 Svelte、Rust、PAM、桌面截图或系统控制。字体与三维纹理由本地静态目录提供。登录的请求状态驱动三维验证与黑橙错误主题，登录成功只由现有 HTTP 接口决定。

配色：灰白 #e7e5e1、玻璃 #f6f5f2、墨黑 #111214、灰 #5d5c57、荧光绿 #b9e432、警示橙 #ff7b00。Montserrat 用于英文标识、JetBrains Mono 用于元数据，中文采用系统无衬线。登录保留上游三维 ∞ 与档案卡构图；工作区改为左侧导航和可滚动档案面板，保持内容密度与可读性。窄屏改为自然纵向布局。

选择实际移植三维模块，而非 CSS 近似；选择 Vue 重写界面层，而非嵌入独立 Svelte 应用。已有 lockscreen/ 与 archive-desk/ 不作为生产依赖，不修改。

## 实施

- [x] 保存现有前端快照，移入来源文件、字体、纹理与许可证。
- [x] 新增 RhineMark、RhineClock、RhineScene Vue 组件；三维延迟加载、暂停、不可见停止、卸载释放、减少动态效果与 WebGL 降级。
- [x] 登录页与现有登录接口连接；用户名/密码、忙碌、失败、重试、成功和会话错误保持可用。

- [x] 构建、针对认证状态的组件回归、本地隔离模拟 API 浏览器验证（桌面与窄屏）。

## 边界

不部署公网，不连接或写入真实资料，不修改认证、业务 Python 后端、会话策略或设备配置。验证时发现 Windows 的 `.js` 静态 MIME 是 text/plain，针对性修改 `web_frontend.py` 注册标准 MIME，并新增回归测试。不把模拟 API 验证描述为真实 PostgreSQL、模型调用或公网业务验收。保留原有未提交改动，任务完成不自动提交。

## 实测结果

前端 3 项回归（2 项认证组件，1 项实际 Stage 资源释放）通过；Python 50 项回归通过。生产构建成功，三维独立块 gzip 约 241 kB。使用生产静态路由加内存示例 API 验证登录各状态、筛选、详情、检索来源、回收恢复与退出；375/768/1024/1440px 检查，375px 工具区同时展开无横向溢出。减少动态效果实测静态 SVG + 0s 过渡。独立复核发现上游遗漏灯光阴影的显式释放，已补齐并以真实 Three 对象验证释放事件；没有测量显存回收量。上游驱动着色器存在编译 warning，最终 error 日志为空。

截图、快照、命令和明确未验收范围见 HANDOFF 最新段落。真实上传、处理、检索和公网流程没有在本轮执行。
