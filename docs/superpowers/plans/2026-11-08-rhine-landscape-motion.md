# Rhine 横屏切换复核与重做

## 已确认的问题与选择

本轮用户要求仔细对照原项目，并只处理横屏。上一版只复用了时点，使用 View Transition 横纵拉伸、线性位置插值，并在 560ms 卸载三维场景，不能还原原版 SnapCard 飞行和持续解体。

对照来源为 rhine-lock commit a4df68c 的完整 transition.ts、App.svelte 和演示 lock-unlock.webp。原演示 102 帧/5.65 秒，已制作联系表检查入场、验证和还原画面。保留源公式，采用实际 Vue 资料库视口替代桌面截图：不引入截图库，不伪造桌面，不保存个人资料图片。

## 横屏证据与边界

四个视口 1920×1080、1366×768、1024×768、2560×1080：没有横向溢出，提交按钮处于视口内。1440×810 录制下，飞行期间保持 canvas；最终资料库宽度与飞行内容宽度均为 1425px，清除内联飞行样式后保持同一 DOM。最终浏览器 error 为空，不能等同于所有显卡无 shader warning。

几何单测和逐帧录制支持上述结论，不将其作为真实数据库/模型/公网验收或长期性能证据。竖屏不在本轮验收范围。源码、截图、录制位置及预览命令见 HANDOFF 最新段落与 frontend/README。
